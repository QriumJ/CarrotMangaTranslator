# v3.7.6

복구 이력이 1 GiB 또는 4,096개에 도달하면 채팅의 첫 편집·이미지 저장까지 막히던 문제를 수정했습니다. 앱이 오래된 일반 편집 이력을 자동 순환시키며 저장을 계속합니다.

## 채팅 저장과 복구

- 일반 페이지 편집 이력은 최대 7일 동안 보관하며, 1 GiB·4,096개를 자동 정리 목표로 사용합니다. 보호 중인 기록 때문에 목표를 초과해도 그 이유로 새 저장을 거부하지 않습니다.
- 출력물, 삭제 원본 복구본, 가져오기·이동·문맥 변경·워크플로 기록은 일반 편집 이력 예산과 분리합니다. 진행 중 작업, undo/redo와 부모 작업이 참조하는 기록은 연결 간에도 보호합니다.
- 새 페이지·복구본 저장과 오래된 이력 정리를 같은 트랜잭션으로 처리합니다. 저장 실패 시 함께 롤백하며, 커밋 이후 중단된 정리는 기존 재시작 복구 경로가 마무리합니다.
- 기존 암호화 목록은 첫 쓰기에서 256항목 단위의 목록 페이지로 전환합니다. 기록 ID·소유자·기존 payload를 유지하며 전체 목록의 4,096개 제한으로 저장을 차단하지 않습니다.
- 정리된 이력은 원래 만료 시각까지 식별 정보를 남깁니다. 도구 응답과 번역 가이드는 이전 복구본 정리를 정상 저장 실패나 작업 재실행 사유로 안내하지 않습니다. 실제 저장장치 부족은 별도 오류로 구분합니다.

보관함, 원본, 현재 편집 이미지와 사용자 출력 파일은 용량 정리 대상이 아닙니다. 새 설정이나 수동 청소 절차 없이 적용됩니다. 새 목록 형식으로 전환한 데이터 프로필을 이전 버전에서 직접 여는 것은 지원하지 않습니다. 이전 버전으로 돌아갈 때는 변경 전 전체 데이터 프로필 백업을 사용해야 합니다.
