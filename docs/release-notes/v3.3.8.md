# v3.3.8

오류 보고 버튼으로 보내는 진단 정보를 보강했습니다. 작업이 멈추거나 실패했을 때 어떤 실행의 어느 단계에서 문제가 생겼는지 확인하기 쉬워지고, 긴 보고서도 GitHub에 핵심 정보가 자동 입력됩니다.

## 오류 보고 정보 보강

- 작업 ID·실행 ID·오류 발생 시각을 연결하고, 실행 당시 모델·생성 한도·OCR·인페인팅 설정을 보고 시점 설정과 구분합니다.
- 현재 작업과 최근 실행의 상태, 마지막 진행 시각, 취소 요청, 실제 진행량을 포함합니다. 번역 작업의 진행 중 단계·페이지·정리 단계도 기록합니다.
- 원래 오류의 stack·cause와 복수 오류를 보존하고, 뒤에서 치명적 오류나 취소가 발생해도 앞선 페이지 실패가 누락되지 않도록 했습니다.
- 관련 진행 로그와 오류 로그를 함께 수집합니다. 큰 로그 한 줄이나 많은 진행 메시지가 원인 오류를 밀어내는 문제를 줄이고, 생략·축약 여부를 표시합니다.
- 별도로 설정한 로그 경로를 따르며, 설정·GPU·실행 기록 수집이 지연되면 제한 시간 후 수집된 정보로 보고서를 만듭니다.

## 보고 실패와 상태 표시 수정

- 긴 보고서는 GitHub 본문에 오류·환경·최근 로그 요약을 자동 입력하고 전체 내용을 클립보드에 복사합니다. 붙여넣기를 생략해도 안내문만 제출되지 않습니다.
- 한글·이모지의 바이트 경계와 오류 메시지 길이 제한을 통일해 보고서 생성이 거부되는 문제를 수정했습니다.
- 같은 작업을 재개한 뒤 다시 실패해도 새 실행의 오류 보고 알림이 나타나며, 이전 실행의 오류·진행 정보가 섞이지 않도록 했습니다.
- 취소·실패·부분 실패를 전체 완료량으로 표시하지 않고 마지막 실제 진행량을 유지합니다.

## 공개 보고서의 원문 보호

- 모델 응답 파싱 오류에는 원문 미리보기 대신 응답 구조와 길이를 기록합니다.
- 이전 버전 로그에 원문 미리보기가 포함된 오류는 해당 진단을 생략해 공개 이슈로 다시 전송되지 않도록 했습니다. API 키·헤더·원문·파일 경로를 실행 설정 정보에 추가 수집하지 않습니다.

## 검증

- 전체 테스트 10,868개와 커버리지 기준, 정적 검사, 빌드·스모크 검사를 통과했습니다.
- 긴 한글·이모지 보고서, 로그 폭주, 재개 직후 실패, 취소·후속 실패 시 오류 보존, 수집 제한 시간과 공개 본문 정제를 회귀 테스트로 확인했습니다.
- 실제 오류 보고 화면을 넓은 창과 좁은 창에서 확인했습니다. 플랫폼별 설치 파일은 릴리스 workflow에서 패키징·실행 검증합니다.
