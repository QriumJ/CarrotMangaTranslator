# v3.3.2

Windows 네이티브 추론에서 GPU 커널 파일이 있어도 찾지 못하고 종료되던 경로 처리 문제를 수정했습니다. AMD FLUX 오류 제보 [#147](https://github.com/ucx0204/CarrotMangaTranslator/issues/147)를 바탕으로 공통 DLL 로더와 실행 환경을 함께 보완했습니다.

## 네이티브 추론 안정성

- Windows 확장 경로 접두사와 GPU 라이브러리의 슬래시 경로 조합 때문에 커널 파일 탐색이 실패하던 문제를 수정했습니다. FLUX, LaMa/AOT와 ROCm 장치 확인이 사용하는 공통 네이티브 로더에 적용됩니다.
- 한글·공백·긴 경로와 UNC 경로의 처리를 보강했습니다. 긴 경로를 지원하지 않는 일부 DLL에는 기존 Windows 짧은 디렉터리 별칭을 사용하며, DLL 파일명과 종속 라이브러리 검색 정책은 유지합니다.
- 실행 시 앱이 제공하는 `PATH`, `HIP_PATH`, `ROCM_PATH`도 네이티브 라이브러리가 하위 경로를 안전하게 결합할 수 있도록 정규화합니다.
- 수정된 Windows FLUX·LaMa/AOT 실행 파일을 포함합니다. 원본 이미지, 출력물, 모델과 GPU 선택 설정은 변경하지 않습니다.

## 검증 범위

- 긴 한글·공백 경로에서 DLL 로딩과 커널 파일 읽기를 재현하는 Windows 회귀 테스트를 추가했습니다. 드라이브·UNC 경로 사례를 Rust와 TypeScript에서 함께 검사합니다.
- 로컬 RTX 4090에서 긴 경로를 사용한 FLUX CUDA, LaMa CPU/CUDA, AOT CPU/CUDA 실제 추론을 확인했습니다.
- RX 9060 XT / gfx1200의 실제 AMD GPU 추론은 별도 하드웨어 검증이 필요합니다. 해당 모델 패키지에 제보된 커널 파일이 포함되어 있음을 확인했으며, 기존 GPU 패키지는 교체하지 않았습니다. 짧은 경로 별칭이 없는 볼륨에서는 외부 DLL 자체의 긴 경로 제한이 남을 수 있습니다.

## 설치 파일과 서명

- **Windows 10/11 x64:** `CarrotMangaTranslator-Setup-v3.3.2.exe` — 코드 서명 없음.
- **Apple Silicon macOS 14 이상:** `CarrotMangaTranslator-3.3.2-macOS-arm64.dmg` / `.zip` — ad-hoc 서명, Apple 공증 없음. Intel Mac은 지원하지 않습니다.
