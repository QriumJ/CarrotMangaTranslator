# 말풍선 여백·선택 편집·진행량 (2026-10-21)

## 동작 계약

- 글자 배치용 Koharu 마스크에서 글자 크기·외곽선 두께·정책에 따른 숨은 erosion을 제거했다. 여백 0%는 감지된 모양에 추가 축소를 하지 않는다. 감지 오차 자체를 보정하거나 모든 글자가 테두리에 닿게 하는 설정은 아니다.
- 기존 0–70% 범위와 기본 12%를 유지한다. 비율은 각 축의 전체 축소율이다. 12%이면 원래 폭·높이의 88%를 사용한다.
- 원문 지우기는 별도 경로다. 기존 1px 경계 보호, 내부 구멍 처리, 소유 영역 분리와 원문 마스크는 유지한다. 글자 여백 설정을 원문 지우기에 적용하지 않는다.
- 이어진 말풍선의 블록 간 소유 영역 분리는 유지한다. 의도적으로 테두리에 겹치는 배치는 기존 블록 이동·확대·수동 영역 편집을 이용할 수 있다.
- 서식의 블록 전체 설정에서 여백을 입력하고 명시적으로 적용한다. 선택된 블록들만 다시 감지·배치하며 원문·번역문·문자 서식·원본 이미지를 바꾸지 않는다. 이미 축소된 영역만 있는 과거 문서도 재감지로 복구한다.
- `TranslationBlock.bubbleLayoutPaddingRatio`에 성공한 블록별 값만 저장한다. 값이 없으면 전역 설정을 따른다. 명시적 요청 > 블록별 값 > 전역 값 순서다. 요청 실패·감지 불일치 시 초안 값은 저장하지 않는다.
- 여백과 배치 좌표는 한 편집 기록으로 실행 취소·재실행한다. 이전 기록에 여백 필드가 없으면 기존 호환 동작을 유지한다.
- 다중 선택의 자동 지우기 제외는 모든 선택 블록을 같은 값으로 설정한다. 이미 지운 픽셀을 복원하거나 즉시 지우기를 실행하는 기능은 아니다.
- 페이지 작업 진행은 페이지 수와 단계 수를 함께 표시한다. 80페이지 × 7단계의 560은 단계 작업 수이며 번역을 7회 반복한다는 뜻이 아니다. 기존 수치 진행률 계산은 유지한다.
- 사용자 요청에 따라 여백 입력에는 설명 문장과 툴팁을 넣지 않는다. 이름·숫자·적용 버튼만 표시한다.
- 패널은 전역 기본값을 반영한 실제 여백으로 혼합 여부를 판단한다. 여러 블록 적용 후에는 감지 성공 개수를 추정하지 않고 변경된 배치 개수를 표시한다. 명시적으로 빈 선택을 보내면 페이지 전체 실행으로 확장하지 않는다.

## 주요 경로

- 마스크: `src/main/bubbleLayout/koharuMaskRefinement.ts`
- 배치: `src/main/bubbleLayout/bubbleLayoutPageProcessor.ts`
- 선택별 요청: `src/shared/inpaintingTypes.ts`, `src/shared/ipcJobSchemas.ts`
- 적용·실행 취소: `src/main/inpainting/bubbleLayoutRunner.ts`, `inpaintingLayoutState.ts`
- 진행 메타데이터: `src/main/jobs/pageWorkflowJob.ts`, `src/shared/jobTypes.ts`
- 실제 작업 이벤트 수신: `src/renderer/src/hooks/jobEventState.ts` (같은 작업의 업데이트에서 유지하고 다음 작업에서는 초기화)
- UI: `src/renderer/src/components/EditorBubbleLayoutSettings.tsx`, `JobProgressReadout.tsx`

감지 모델 자산은 바꾸지 않았다. 배치 알고리즘 식별자만 `explicit-padding-v2`로 갱신했다. 문서를 열 때 저장된 좌표를 일괄 변경하지 않는다. 새로운 규칙은 다시 적용한 블록부터 사용한다.

## 검증 기록

변경 전에 기존 핵심 51개 테스트 및 원문 지우기 마스크 특성 검사를 통과시켰다. 변경 후 말풍선·지우기·기록·작업 진행 관련 36개 파일, 275개 테스트를 통과했다. 0%의 원래 경계, 큰 글자·두꺼운 외곽선에서의 불변성, 70% 축소, 원문 지우기 불변성, 선택 ID 검증, 실패 시 미저장, 실행 취소 및 기존 기록 호환성을 포함한다.

최종 `npm run check`의 27개 검사를 모두 통과했다 (516.72초). 테스트 11,268개 통과, 기존 환경 의존 테스트 9개 건너뜀; 1,436개 파일 통과, 1개 파일 건너뜀. 타입 검사, 린트, 아키텍처·유지보수 규칙, 기존 커버리지 하한, 빌드와 번들 검사를 포함한다. 커버리지 하한은 낮추지 않았다.

같은 검사 실행의 production 화면·내보내기 픽셀 비교는 두 표본 모두 불일치 0픽셀, 채널 차이 0이었다. PSD의 배경·텍스트 레이어·알파 검사와 긴 경로 이미지 프로토콜 검사도 통과했다. 로그는 `.tmp/bubble-final-check4.log` 및 `.tmp/check-logs/`에 있다. 앱 릴리스와 커밋은 만들지 않았다.

실제 production `EditorPanel`과 진행 표시 컴포넌트를 사용한 최종 캡처:

- `C:/tmp/bubble-padding-wide400-single-v2.png`: 넓은 패널, 전역 여백 30% 상속.
- `C:/tmp/bubble-padding-rail300-mixed-v2.png`: 300px 패널, 여러 블록 혼합 상태.
- `C:/tmp/bubble-padding-zoom2-draft-v2.png`: 200% 확대, 여백 초안과 적용 버튼.

설명 문장·툴팁이 없는 최종 상태를 캡처했다. 넓은·좁은·확대 화면의 여백 입력, 적용 버튼, 제외 체크박스, 진행량 표시에서 겹침이나 가로 잘림이 없음을 직접 확인했다. 임시 QA 엔트리는 최종 소스에서 제거했고 캡처는 보존했다.
