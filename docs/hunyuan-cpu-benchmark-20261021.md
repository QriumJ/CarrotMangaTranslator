# HunyuanOCR 1.5 CPU 속도 실측 — 2026-10-21

## 측정 범위

현재 PC의 AMD Ryzen 9 7950X(16코어/32스레드)에서 CPU 16스레드와 RTX 4090 CUDA를
순차 실행했다. llama.cpp b11103과 앞선 시험의 동일 GGUF를 사용했다.
F16·Q4_K_M·Q5_K_M 텍스트 모델 모두 F16 vision 모델로 통일했다.
CPU는 `--device none -ngl 0 --no-mmproj-offload --no-op-offload --no-kv-offload`,
`CUDA_VISIBLE_DEVICES=-1`로 GPU 사용을 차단했다. 로그에서 텍스트 가중치·KV·연산 버퍼 및
이미지 인코더가 CPU backend임을 확인했다. CUDA 초기화 실패 메시지는 이 GPU 차단의
예상 결과이며, 서버와 추론은 CPU로 진행됐다.

기존 고정 표본에서 중국어 자동 영역 8개(4개 분류별 중간/최대 글자 수),
일본어 4개(3개 작품의 중간 길이 및 가장 긴 영역)를 선택했다.
선택 기준은 이번 측정 전 고정했으며 쉬운 출력이나 빠른 결과를 보고 고르지 않았다.
한 영역으로 예열한 뒤 동일 12영역을 두 번 순서대로 실행했다.
모델×장치별로 총 24개의 측정 요청을 사용했다.

큰 이미지 시험은 기존 중국어 CCC 페이지 `ccc-03-0.png`, 1748×2480이다.
CPU Q5 시험은 요청 후 3분 이상 결과가 나오지 않아 수동 시간 제한으로 중단했다.
서버 실행부터 종료까지 234.25초, 초기화와 요청 전 준비는 약 2초였다.
완료 시간을 추정해 성공 결과로 표시하지 않았다. 이후 CPU F16·Q4의 전체 페이지 시험은
생략하고 세 모델의 영역 인식 속도 비교에 집중했다. GPU는 모델별 새 서버에서 페이지를
한 번씩 완료했다. 페이지 전체의 탐지 정확도를 평가하는 시험은 아니다.
기존 연속 페이지 네이티브 크래시의 해결 여부를 검증하는 시험도 아니다.
중단 시 로그는 이미지 인코딩 단계였다. 이 장시간 미완료가 연산량 때문인지
CPU backend의 별도 문제인지 정밀 진단하지 않았으므로 CPU 전체 페이지의 일반적인
완료 시간으로 확대 해석하지 않는다.

HTTP 요청 시작부터 OCR 결과 수신까지를 측정했다. 모델 로드·이미지 파일 읽기·PNG 인코딩은
표의 추론 시간에 포함하지 않았다. 탐지·번역·식자·앱 화면 갱신은 포함하지 않았다.
GPU 비교도 이번 CPU 시험과 같은 입력을 다시 실행했다.

## 결과

| 모델   | CPU 영역당 평균 | GPU 영역당 평균 | CPU/GPU 시간 비율 | GPU 전체 페이지 |
| ------ | --------------: | --------------: | ----------------: | --------------: |
| F16    |         3.121초 |         0.130초 |            24.1배 |          2.76초 |
| Q4_K_M |         2.743초 |         0.110초 |            24.9배 |          2.67초 |
| Q5_K_M |         3.000초 |         0.123초 |            24.3배 |          2.63초 |

영역 평균은 각 24요청, 전체 페이지 값은 각 1요청이다. 작은 표본의 실제 관측치이며
CPU 제품군 전체나 임의의 긴 웹툰 처리 시간을 보장하지 않는다.
7950X의 AVX512 등 CPU 기능을 사용하는 런타임에서 측정했고, 다른 CPU·메모리·전원 설정과
스레드 수에서 결과가 달라질 수 있다. CPU 스레드 수별 최적화 탐색은 하지 않았다.
이 값은 측정한 GGUF/llama.cpp 구현의 속도이지 CPU에서 가능한 모든 구현의 속도 한계가 아니다.

## 반복과 출력

- F16: CPU 두 번째 12영역 합계 37.50초, CPU 반복 문자열 일치 12/12, GPU 반복 12/12, CPU/GPU 두 번째 실행 문자열 일치 11/12. GPU 전체 페이지 출력 67 tokens.
- Q4_K_M: CPU 두 번째 12영역 합계 32.86초, CPU 반복 문자열 일치 12/12, GPU 반복 12/12, CPU/GPU 두 번째 실행 문자열 일치 11/12. GPU 전체 페이지 출력 66 tokens.
- Q5_K_M: CPU 두 번째 12영역 합계 35.79초, CPU 반복 문자열 일치 12/12, GPU 반복 12/12, CPU/GPU 두 번째 실행 문자열 일치 10/12. GPU 전체 페이지 출력 66 tokens.

이번 시험은 속도 비교다. 장치별 수치 연산에 따라 출력이 달라질 수 있으며,
이 12영역만으로 CPU 정확도가 기존 234영역 평가와 같다고 주장하지 않는다.
중단한 CPU 전체 페이지 요청 외에는 출력 상한 도달 없이 정상 stop으로 종료했다.

## 공통 설정과 자료

- 잘린 영역 16px 흰 여백, context 4,096. 전체 페이지 context 10,240.
- parallel 1, logical batch/microbatch 512/512, Flash Attention on.
- CPU threads/batch threads 16, GPU 실행의 CPU threads 4.
- temperature 0, top_k 1, top_p 1, min_p 0, seed 123,
  repeat penalty 1.08, repeat_last_n=context, max output 384 tokens, prompt cache off.
- 동일 중국어 프롬프트:
  `提取图片中的所有文字，按照阅读顺序输出原文，不要翻译，不要解释。`
- 별도로 다운로드하거나 잘린 이미지를 파일로 저장하지 않았다.
  기존 이미지에 읽기만 수행했고 실행 전후 SHA-256을 검증했다.
  보관함 원본과 앱 코드·설정은 변경하지 않았다.
