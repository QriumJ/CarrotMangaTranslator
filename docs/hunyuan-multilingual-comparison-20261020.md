# HunyuanOCR 1.5 일본어·영어·스페인어 실측 — 2026-10-20

## 결론

이 표본에서는 일본어 만화 본문 인식에 기존 Hayai v2를 유지하는 것이 타당하다.
HunyuanOCR 1.5는 영어의 기울어진 포스터와 스페인어에서 더 정확했다.
영어 일반 대사는 두 모델 모두 잘 읽었으므로 영어 전체에서 큰 차이가 난다고
일반화해서는 안 된다. 앱 코드·모델 기본값·사용자 설정은 바꾸지 않았다.

## 실제 입력과 정답

- 일본어: 사용자 보관함의 서로 다른 3개 작품, 각 화의 2·4페이지, 총 6페이지
  32개 영역, 정규화 후 384자.
  - 《나는 악역 기사단장으로 환생한다.》 16.3화
  - 《최강의 검성, 미소녀 메이드로 전생해 빗자루로 무쌍하다》 10.2화
  - 《제국 우주군 소속인 나, 미개척 행성에 조난당했습니다.》 8화
- 영어·스페인어: David Revoy와 번역 기여자들의 공개 만화
  **Pepper & Carrot** 1화 1–3페이지, 3화 1–7페이지.
  각 언어 10페이지·34개 영역. 영어 1,031자, 스페인어 1,124자.
  같은 작품의 두 언어판이므로 독립적인 여러 작가·글꼴 표본은 아니다.
  - [영어 1화](https://www.peppercarrot.com/en/webcomic/ep01_Potion-of-Flight.html)
  - [스페인어 1화](https://www.peppercarrot.com/es/webcomic/ep01_Potion-of-Flight.html)
  - [영어 3화](https://www.peppercarrot.com/en/webcomic/ep03_The-secret-ingredients.html)
  - [스페인어 3화](https://www.peppercarrot.com/es/webcomic/ep03_The-secret-ingredients.html)
  - 작가가 Creative Commons Attribution으로 공개한 판본을 공식 사이트에서 받았다.
    각 다운로드 URL·SHA-256·크기·출처·저작자 정보는 `pages.json`에 있다.

총 26페이지에서 **100개 영역**을 선정했다. 대사·나레이션·작은 주석·기울어진
포스터를 포함한다. 큰 효과음과 문장부호만 있는 영역은 평가하지 않았다.
원본 이미지를 읽어 수동으로 영역을 정하고 모델 실행 전 직접 눈으로 전사했다.
기존 보관함의 OCR 결과는 정답으로 사용하지 않았다.
이는 **assistant 전사 표본이며 독립 검증된 human gold가 아니다.**

일본어 정답은 번역 입력으로 쓸 본문이며 후리가나를 제외한다.
100개 잘린 이미지를 직접 확인한 후, 추론 전 일본어 2개 영역의 아래쪽 잘림을
수정했다. 최초 초안과 수정 기록을 보존했다. 추론 후 정답·좌표를 변경하지 않았다.
최종 `references.json` SHA-256:
`151aff2226dcb893bc1057dd69e79cee57faf20d75fec2138ea4ffd95122c407`.

전체 페이지 탐지 재현율이나 번역·식자 품질을 평가한 실험은 아니다.
같은 원본에서 같은 좌표로 잘라 모델별 인식 성능을 비교했다.

## 조건

- 기존 Hayai v2:
  `JustANormalTinkerer/hayai-ocr-v2@53aed13296a9d39bd7c0c0bcba745010d8142b5b`.
  변경하지 않은 production `hayai-bboxes.py`의 loader와 batch recognizer 사용.
  256 patches, batch 8, 최대 128 tokens. 각 조건을 3회 실행해 모든 출력 일치를 확인.
- HunyuanOCR **1.5**:
  `tencent/HunyuanOCR@47644ecc4fc854efa4f505155158831f36773ee4`.
  앞선 중국어 실험에서 검증한 동일 로컬 가중치 재사용.
  Transformers native loader, BF16, SDPA, batch 1, greedy,
  repetition penalty 1.08, 최대 384 tokens.
- RTX 4090. 각 모델의 기존 격리 환경 사용. 새 패키지 설치나 환경 변경 없음.
- 두 모델 모두 잘린 영역 그대로와 **16px 흰 여백**을 추가한 조건을 실행.
  원본의 이웃 글자를 더 포함하는 확장은 하지 않았다.
- Hunyuan 기본 지시:
  `提取图片中的所有文字，按照阅读顺序输出原文，不要翻译，不要解释。`
- 후속 진단 조건은 일본어에만
  `日文只输出正文，不要输出振假名（注音）。`
  를 추가. 같은 표본을 본 뒤 실행한 진단이며 독립적인 검증 표본은 아니다.
- 점수: NFKC 후 문자·숫자만 남긴 Levenshtein 편집거리.
  공백·문장부호 제외, **대소문자·스페인어 악센트·ñ·일본어 작은 가나 유지**.
  완전일치는 이 정규화 이후 기준이다. 원문 문장부호까지 완전히 동일하다는 뜻은 아니다.
  대소문자를 무시한 점수도 JSON에 별도로 저장.

## 전체 결과

각 셀은 **문자 오류 수 · 완전일치 영역 수**이다. 낮은 오류와 높은 완전일치가 좋다.

| 설정                                   | 일본어 / 384자 · 32영역 | 영어 / 1,031자 · 34영역 | 스페인어 / 1,124자 · 34영역 |
| -------------------------------------- | ----------------------: | ----------------------: | --------------------------: |
| Hayai v2, 여백 없음                    |              **1 · 31** |                 65 · 33 |                     155 · 5 |
| Hayai v2, 16px 여백                    |                  2 · 31 |                 60 · 32 |                     162 · 5 |
| Hunyuan 1.5, 여백 없음                 |                 61 · 18 |                  1 · 33 |                      2 · 32 |
| Hunyuan 1.5, 16px 여백                 |                 87 · 17 |              **0 · 34** |                  **2 · 32** |
| Hunyuan 1.5, 16px + 후리가나 제외 지시 |                 88 · 15 |                  0 · 34 |                      2 · 32 |

5조건 × 100영역을 평가했다. Hayai의 3회 반복까지 포함하면 총 900회 영역 인식이다.
Hunyuan의 후속 실행에서 지시가 바뀌지 않은 영어·스페인어 68개 출력은
이전 16px 실행과 문자열 단위로 모두 같았다. Hunyuan 출력 상한 도달은 없었다.

## 오류 해석

### 일본어

Hunyuan은 후리가나를 본문과 함께 출력했다. 기본 지시가 '모든 글자 추출'이므로
후리가나 포함 자체를 글자 판독 실패와 동일시해서는 안 된다. 하지만 이를 제외하라는
명시적 지시를 추가해도 번역용 본문 출력 문제는 해결되지 않았다.

후리가나가 없는 **26영역·287자만** 따로 계산해도 Hayai 1오류,
Hunyuan 기본 조건 18오류, 후리가나 제외 지시 조건 16오류였다.
따라서 차이가 정답의 후리가나 제외 규칙에만 의존하지 않는다.

Hunyuan은 `ふふん → 不不ん`, `ふむ → 不屯`처럼 가나를 한자로 읽고,
`こりゃ悪くねぇなぁ → こりや悪くねえなあ`처럼 작은 가나를 바꾸었다.
일부 조건에서 본문 누락도 발생했다.
Hayai의 여백 없는 조건에서 유일한 오류는 `チイッ → チィッ`였다.
이런 작은 글자 크기의 판별은 수동 전사 불확실성이 있으나 전체 결론을 바꾸지는 않는다.

### 영어

Hayai의 65오류는 **기울어진 포스터 한 영역에 집중**됐다.
포스터를 제외한 33영역·941자는 여백 없는 Hayai와 Hunyuan 모두 0오류였다.
따라서 이번 결과는 Hunyuan의 복잡한 장면 글자 처리 이점을 보여 주며,
일반 영어 말풍선에서 Hayai가 전반적으로 나쁘다는 근거가 아니다.

### 스페인어

포스터를 제외해도 33영역·1,031자에서 Hayai 87오류,
Hunyuan 16px 조건 2오류였다.
Hayai는 `señor → sehor`, `mañana → maiiana`, 악센트 누락,
`¡`·`¿`를 `i`·`j` 같은 문자로 오인하는 문제가 반복됐다.

Hunyuan 16px의 두 오류는 `¡ah → iah`, `¡es → jes`로,
뒤집힌 느낌표를 알파벳으로 잘못 읽은 경우였다.
이는 문장부호를 점수에서 제외해도 잘못 생성한 알파벳이 남으므로 오류로 계산된다.

## 실행 시간과 범위

모델 로딩·이미지 파일 읽기를 제외한 관측치:

| 조건                | 일본어 32영역 | 영어 34영역 | 스페인어 34영역 |
| ------------------- | ------------: | ----------: | --------------: |
| Hayai v2, 여백 없음 |        0.67초 |      1.68초 |          2.07초 |
| Hunyuan 1.5, 16px   |       12.11초 |     10.28초 |         15.18초 |

Hayai는 batch 8의 반복 2–3회 평균, Hunyuan은 batch 1의 순차 실행이다.
모델·배치·런타임이 다른 현재 테스트 구현의 시간이며 최적화된 배포 속도 비교가 아니다.
이 수치만으로 보편적인 속도 배수를 주장하지 않는다.

## 검증·보존

실험 디렉터리: `.tmp/hunyuan-multilingual-20261020/`.

- `pages.json`: 출처, 원본 경로, SHA-256, 크기.
- `labels.py`, `references.json`, `preflight-changes.json`: 추론 전 전사와 좌표.
- `run_hayai.py`, `run_hunyuan.py`: 재현 스크립트.
- `results/*.json`, `errors.json`, `subsets.json`: 설정별 원문 결과·오류·부분집합.
- `verification.json`: 모든 결과의 입력 동일성, 별도 편집거리 구현 재검산,
  26개 입력 이미지 SHA-256, 보관함 원본 6개 보존, 반복 출력 일치 확인.
- `cleanup-manifest.json`: 이번 실험에서 생성한 다운로드·미리보기만의 명시적 목록.
- `cleanup-result.json`: 다운로드 원본 20개, 생성 미리보기·검토 이미지 39개,
  내려받은 HTML 4개, **총 63개 임시 파일 삭제 완료**.
  파일마다 실험 폴더 경계·일반 파일 여부·SHA-256을 확인하고 개별 삭제했다.
  재귀 삭제는 사용하지 않았으며 보관함 원본 6개는 삭제 전후 SHA-256이 같았다.
  사용자 요청에 따라 이미지 사본은 남기지 않고 출처·좌표·전사·추론 결과·스크립트만 보존했다.

앱의 production adapter SHA-256은 전후 동일:
`f5284ca7835f7d88549021b15a5c70f85779285ef29dbf20e20369876aec1903`.
앱 소스 수정이 없으므로 앱 전체 빌드·UI QA를 이 OCR 실험의 검증으로 대신하지 않았다.
검증은 실제 모델 실행과 결과 재검산으로 수행했다.
